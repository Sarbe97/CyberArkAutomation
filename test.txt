# Technical Description: Custom Lenovo LXCC (XClarity Controller) Redfish CPM Plugin

## 1. Executive Summary & Root Cause
The standard CyberArk Marketplace plugin for Lenovo LXCC (`LenovoLXCCPlugin`) fails in enterprise environments across multiple server generations due to limitations in Lenovo BMC Redfish implementations:
* **Brittle Query Expansion**: The OOTB plugin relies on OData query parameters (`/redfish/v1/AccountService/Accounts?$expand=.&$select=Members/UserName`) to dynamically locate the account. Many Lenovo XCC firmware versions do not support `$expand` or return truncated stubs, resulting in `HTTP 400 Bad Request` or parsing failures.
* **HTTP 428 (Precondition Required)**: Lenovo XCC requires an `If-Match` header on `PATCH` operations to prevent mid-air collisions. OOTB lacks this header, causing password changes to fail.
* **Firmware Password Constraints**: The OOTB policy generates 20-character passwords, causing `HTTP 500 Internal Server Error` on older BMC firmware with strict 14–16 character limits.
* **Variable Slot Numbers**: Across 100+ enterprise servers, target administrative accounts do not consistently sit in Slot 1; they are distributed across Slots 1, 2, or 3.

To resolve these issues, we engineered **`LenovoLXCC-Custom`**, replacing dynamic collection expansion with **direct, pre-validated Slot targeting (`SlotID`)**, adding concurrency protection headers, and developing an **automated bulk slot discovery script**.

---

## 2. Technical Modifications (What Was Changed)

### A. Direct Slot Targeting via Dynamic Variable (`SlotID`)
* **Standard Plugin**: Queried all accounts dynamically and attempted complex JSONPath extraction with substring manipulation:
  ```xml
  <!-- OOTB LenovoLXCC: Brittle & Fails on older firmware -->
  <endpoint>/{{novalidate:{{substring:useridendpoint:startIndex}}}}</endpoint>
  ```
* **Custom Plugin**: Direct REST targeting using a configurable account-level property `{{SlotID}}` (defaulting to `2`):
  ```xml
  <!-- LenovoLXCC-Custom: Direct, deterministic endpoint -->
  <endpoint>/redfish/v1/AccountService/Accounts/{{SlotID}}</endpoint>
  ```

---

### B. Mandatory Concurrency Header (`If-Match: *`)
* Added `<If-Match>*</If-Match>` to both `ChangePassword` and `ReconcilePassword` `PATCH` requests to satisfy Lenovo XCC's HTTP 428 Precondition requirement:
  ```xml
  <RequestWrapper>
    <request name="ChangePassword">
      <general>
        <endpoint>/redfish/v1/AccountService/Accounts/{{SlotID}}</endpoint>
        <method>PATCH</method>
      </general>
      <header>
        <Accept>application/json</Accept>
        <Content-Type>application/json</Content-Type>
        <Authorization>Basic {{username}}:{{pmpass}}</Authorization>
        <If-Match>*</If-Match>
      </header>
      <body>
        <json>
          {
            "UserName": "{{username}}",
            "Password": "{{pmnewpass}}"
          }
        </json>
      </body>
    </request>
  </RequestWrapper>
  ```

---

### C. Pre-Rotation Validation & Custom Error Code `8110` (`FAILUserMismatch`)
* **Safety Mechanism**: Before executing a password change, the plugin queries the slot and verifies that `$.UserName` matches the target account `{{username}}`.
* If a mismatched user is detected in the slot, the operation immediately halts to prevent corrupting another user's credential:
  ```xml
  <StatusCode value="200" next="ByParse" condition="OR" nomatch="FAILUserMismatch">
    <Parse name="matchedUser" type="json" value="$[?(@.UserName == '{{username}}')].UserName">
      <Equals value="*" next="ChangePasswordLink"/>
    </Parse>
  </StatusCode>
  ```
* Defined custom return code in `Fails` and `Policy-LenovoLXCC-Custom.ini`:
  ```xml
  <Fail name="FAILUserMismatch" rc="8110" message="Account in slot does not match target username." />
  ```
  ```ini
  UnrecoverableErrors=8101,8102,8110
  ```

---

### D. Password Policy Calibration for BMC Compatibility
In `Policy-LenovoLXCC-Custom.ini`, calibrated password generation rules to ensure 100% acceptance across legacy and modern Lenovo XCC/IMM firmware:
* **`PasswordLength=14`** (reduced from 20; safe upper limit for older BMC firmware).
* **`PreventRepeatingCharacters=Yes`** (enforces BMC dictionary compliance).
* **`PasswordForbiddenChars=<>&\"/`** (prevents JSON payload escaping errors).

---

### E. Platform Definition (`Policy-LenovoLXCC-Custom.xml`)
Registered `SlotID` as an optional property on the platform so it can be viewed, edited in PVWA, or populated via bulk upload:
```xml
<Properties>
  <Required>
    <Property Name="Username" />
  </Required>
  <Optional>
    <Property Name="SlotID" DisplayName="Account Slot ID (Default is 2)" />
  </Optional>
</Properties>
```

## 3. Extra Deliverables (What We Did Extra)

### Automated Bulk Slot Discovery Tool (`Find-LenovoUserSlot.ps1`)
To onboard 100+ servers without manual GUI inspection of each BMC:
* **Function**: Takes `servers.csv` (`Address`, `Username`, `Password`), queries `/redfish/v1/AccountService/Accounts`, iterates over configured slot URLs, locates the target username case-insensitively, and extracts the exact `SlotID`.
* **Output**: Produces `servers-output.csv` with the discovered `SlotID` column, ready for bulk onboarding via the Password Upload Utility (PUU) or CyberArk REST API.
* **Core Logic**:
  ```powershell
  $accounts = Invoke-RestMethod -Uri "https://$server/redfish/v1/AccountService/Accounts" -Headers $headers
  foreach ($member in $accounts.Members) {
      $detail = Invoke-RestMethod -Uri "https://$server$($member.'@odata.id')" -Headers $headers
      if ($detail.UserName -and ($detail.UserName.Trim().ToLower() -eq $user.Trim().ToLower())) {
          $slotId = $detail.Id
          break
      }
  }
  ```

## 4. Summary Matrix: Standard vs. Custom

| Feature / Capability | Standard OOTB (`LenovoLXCCPlugin`) | Custom Platform (`LenovoLXCC-Custom`) | Technical Benefit |
| :--- | :--- | :--- | :--- |
| **Endpoint Resolution** | Dynamic `$expand=.` query | Direct `.../Accounts/{{SlotID}}` | Eliminates HTTP 400 & unexpanded member errors on older BMCs. |
| **Concurrency Lock** | No `If-Match` header | `<If-Match>*</If-Match>` | Prevents HTTP 428 Precondition failures on `PATCH`. |
| **Slot Safety Check** | None (blind rotate) | Pre-validation matching `{{username}}` | Prevents overwriting the wrong user if slot numbers differ. |
| **Error Handling** | Standard HTTP status | Custom code `8110` for slot mismatch | Added to `UnrecoverableErrors` to halt CPM retry loops. |
| **Password Length** | 20 characters | 14 characters | Prevents HTTP 500 policy rejection on older BMC firmware. |
| **Bulk Discovery Tool** | None (manual lookup) | `Find-LenovoUserSlot.ps1` script | Automates slot discovery across 100+ servers into a ready CSV. |
